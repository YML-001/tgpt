# 中南大学团学组织新闻投稿平台 · 消息与模板

> 适用对象：产品经理、负责消息中心与通知的开发人员
> 代码仓库：https://github.com/YML-001/tgpt （分支 main）
> 在线预览：https://yml-001.github.io/tgpt/
> 依据版本：原型 main 分支 1f9bb5d（2026-10-10），配套文档《功能介绍》《开发需求说明（PRD）》
> 来源标记：**原型已示**表示原型页面中已有这条消息（附原型原文）；**新拟**表示原型只隐含了这个场景、没有给出文案，由本文补拟。

## 一、总体说明

### 1.1 业务流程（本文不改变）

- **学生投稿**：指导老师审核 → 副书记审核 → 一审 → 二审 → 校团委终审。指导老师由投稿人指定：下拉默认本院已配置名单，也可按工号回显后选定。
- **教师投稿**：副书记审核 → 一审 → 二审 → 校团委终审。不指定指导老师，也不选择副书记。
- **职能部门老师投稿**：副职领导审核 → 学生一审 → 学生二审 → 校团委终审。不经过指导老师和副书记。投稿人选择所属部门并指定负责领导（下拉默认该部门在任副职领导，也可按工号回显）。稿件同时进入该部门全体在任副职领导的待办，任一人审核即可。学生一审、学生二审仍由一审员、二审员办理。
- **退回**：任一审核节点退回，稿件都回到投稿人；投稿人修改后重新提交，生成新版本，从首个审核节点重新流转（学生回到指导老师，教师回到副书记，职能部门老师回到副职领导）。退回必须填写意见。
- **终审**：只有“采用”和“不采用”两种结果；不采用必须填写终审意见。采用的稿件计入学院采用统计（统计归档为“计入采用”）。
- **副书记**：投稿人所在学院的副书记，取自学工系统，按学院自动确定，平台不做名单配置。
- **副职领导**：按职能部门在“副职领导名单”中配置。演示人员为党委宣传部副部长秦志远。
- **审核时限**：每个节点默认 3 个工作日，在“业务参数”中按节点配置；剩余不足 1 个工作日（超时预警提前量，可配置）为“即将超时”；超时后记入超时台账。

### 1.2 渠道

| 渠道 | 原型依据 | 说明 |
|------|----------|------|
| 站内消息（PC） | 各角色“消息通知”页；顶部铃铛弹层 | 铃铛显示未读数，弹层展示最近几条消息，可“全部已读”，并有“查看全部消息”入口；消息页分“全部消息 / 未读”两个页签，点击单条消息即标为已读并跳转 |
| 站内消息（移动端） | 各角色移动端“消息”页及底栏角标 | 与 PC 共用同一份消息数据，右上角可“全部已读” |
| 移动端推送 | 超时台账“催办”按钮的提示：“已向某某发送催办提醒（站内消息 + 移动端推送）” | 原型只在催办场景提到推送。PRD 将推送渠道（校内移动门户或企业微信）列为待决问题。建议推送仅用于本文标注“建议推送”的模板 |
| 催办 / 抄送记录 | 统一待办“催办/抄送”页：催办消息、抄送消息两个页签 | 催办、抄送除产生站内消息外，还应写入该页列表 |

原型中没有短信和邮件渠道，本文不拟定这两种渠道。

### 1.3 消息展示约定

- 每条消息包含：图标与颜色、标题、正文、时间、跳转链接、已读状态。原型中的图标和颜色约定如下：
  - 退回：红色撤回图标
  - 终审采用：绿色勾选图标
  - 新的待办：蓝色收件箱图标
  - 已超时：红色警示图标
  - 即将超时：橙色时钟图标
  - 终审未采用：橙色叉号图标
  - 排行榜：蓝色奖杯图标
  - 升华网发布：蓝色地球图标
  - 线索：橙色灯泡图标
  - 系统通知：蓝色铃铛图标
- 时间显示：1 小时内显示“某分钟前”或“1 小时前”；当天显示“今天 时:分”；前一天显示“昨天 时:分”；更早显示“月-日 时:分”。
- 正文中的稿件标题一律用书名号《》包起来。
- 批量通过、批量不通过时，每篇稿件分别发送对应消息，不合并。

### 1.4 发送时机（新拟规则，原型中的时间均为“今天 09:00”）

- 待办到达、审核结果、终审结果：业务动作完成后立即发送。
- 即将超时、已超时的汇总提醒：每个工作日 09:00 统一生成，节假日不发。
- 系统自动催办：节点超时后的第一个工作日 09:00 发送；仍未处理的，此后每个工作日 09:00 再发一次（新拟，频率可在业务参数中配置，见第九节）。
